# Intent Statement — SCD 소통 코칭

## Problem Statement

실제 대화에서 무엇이 어려웠는지 **근거와 함께 돌아볼 방법이 없고, 그 결과가 연습으로 이어지지 않는다**. 대상은 SCD(사회적 의사소통장애)로 의사소통에 어려움을 겪는 사용자다. [Q1]

대화를 마친 뒤 사용자에게 남는 것은 "잘 안 됐다"는 인상뿐이고, 어느 발화에서 무엇이 어긋났는지 짚어주는 수단이 없다. 그래서 다음에 무엇을 연습해야 하는지도 이어지지 않는다. [Q1]

이 서비스는 그 단절을 잇는 것을 목표로 한다: 실제 대화를 녹음·전사하고, 맥락을 확인하고, 근거 발화가 붙은 리포트를 만들고, 거기서 고른 목표를 그대로 모의 대화 연습으로 넘긴다. [Q1][Q3][Q8]

## Target Customer

| 대상 | 설명 | MVP 포함 | Source |
|---|---|---|---|
| 주 사용자 | 13–18세 청소년 | 포함 | [Q2] |
| 보호자·의사소통 지원자 | 결과 열람만 한다. 미성년 사용자에게만 열람 기능을 제공하며, 권한 수준 NONE / SUMMARY / FULL 은 사용자가 고른다. 계정은 사용자가 만들고 초기 권한 기본값은 NONE 이다 | 포함(열람 권한 설정) | [Q2][Q9][Q15][Q16][Q18] |
| 전문가(언어재활사·특수교사) | MVP 제외 | 제외 | [Q2] |

대상 연령 13–18세는 초기 입력 문서의 작업 가정(약 6–12세 아동)을 사용자가 명시적으로 뒤집은 결과다. 이 구간은 전원 미성년자이므로, "미성년자에게만 보호자 열람 제공"이라는 규칙은 이번 MVP에서 모든 사용자에게 열람 기능이 노출된다는 뜻이 된다. 성인 사용자로 확장할 때 이 규칙이 분기점이 된다. [Q2][Q9]

보호자의 역할은 **열람으로 한정한다**. 계정은 사용자가 만들고, 보호자 열람 권한의 초기 기본값은 NONE 이며 사용자 본인이 켠다. 이는 보호자가 계정을 만들고 초기 권한을 정하는 안과 대비해 명시적으로 선택된 결과다. [Q15][Q16]

권한 수준은 **NONE / SUMMARY / FULL 세 단계**를 유지한다. 두 단계로 단순화하는 안과 전체 열람을 빼는 안은 검토 후 선택되지 않았다. [Q18]

사용자가 겪는 불편은 대상별로 다음과 같다. [Q5]

- **주 사용자(13–18세)** — 자기 대화를 이해할 수 있는 말로 돌아보고 싶고, 실패로 규정당하지 않기를 바란다. [Q5]
- **보호자·지원자** — 허용된 범위에서 결과를 열람하고, 데이터 보관과 삭제를 통제하기를 바란다. [Q5]

## Success Metrics

이번 작업의 성공은 **한 가지 기준**으로 판단한다. [Q3][Q11]

| # | 성공 기준 | 측정 방법 | Source |
|---|---|---|---|
| SM1 | 합성 대화 3건이 업로드 → 전사 확인 → 리포트 → 목표 선택 → 모의 대화 → 기록까지 **끊김 없이 이어진다** | 합성 대화 3건 각각에 대해 전 구간을 통과하는 종단 실행이 성공한다 | [Q3] |

SM1 이 보장하는 것과 보장하지 않는 것을 분명히 해 둔다. SM1 은 **여섯 단계가 끊기지 않고 이어지는지**만 본다. 각 단계가 내놓는 판정이 기대와 맞는지는 SM1 의 판정 대상이 아니며, 별도의 수단이 본다. 따라서 종단 실행이 통과했다는 사실만으로 판정이 정확하다고 말할 수 없다. [Q3][Q11][Q20]

근거 발화 ID의 유효성, 보류 사례가 실패로 집계되지 않는 것, 재시도가 첫 시도를 덮어쓰지 않는 것, 전사 정정 시 재검토 표시와 삭제 전파, 화면의 금지 표현 부재 — 이 다섯 가지는 **성공 기준이 아니라 구현 세부사항으로** 다룬다. 이는 성공 기준 범위를 다시 물었을 때 사용자가 SM1 하나로 충분하다고 확인하면서, 나머지를 구현 세부사항으로 다루기로 확정한 결과다. [Q11]

## Initiative Trigger

**AI-DLC 워크플로 검증을 겸한 테스트 MVP**다. 실제 사용자 데이터 없이 합성 데이터로 흐름 전체가 성립하는지 확인하는 것이 주목적이다. [Q4]

이 계기는 범위를 판단하는 기준이 된다: 실제 사용자 데이터 수집과 클라우드 배포는 이 목적에 필요하지 않다. [Q4][desc]

STT·LLM 연동에 대한 기준은 Feasibility 단계에서 한 번 조정되었다. **기본 실행 경로와 성공 기준 SM1 의 검증은 Mock 으로 유지**하되, 실제 제공자에 붙는 live 구현체는 `ANALYSIS_MODE=live` 로만 켜지는 **선택 경로**로 만든다. 따라서 "실제 연동은 필요하지 않다"가 아니라 "실제 연동은 검증 경로 밖의 선택 사항"이 현재 기준이다. 제공자는 아직 정하지 않았다. (Feasibility Q7, F2, F3 → 결정 D-36, D-37) [Q4][desc]

시나리오 원형 6개(`docs/input/06_seed-scenarios.md`)와 UI 문구(`docs/input/03_ui-spec.md`)는 대상 연령 변경에 맞춰 **중·고등학교 생활 배경으로 새로 작성**한다. 조별 과제, 동아리, 급식실·쉬는 시간, 교사와의 대화, 진로 상담이 배경이 된다. 행동 묶음 3종 × 2개라는 구성과 판정 규칙 자체는 유지한다. [Q10][Q12]

합성 테스트 대화 3건(`docs/input/05_synthetic-test-data.md`)은 **그대로 둔다**. 대화 내용이 대상 연령과 크게 상충하지 않는다고 보아 손대지 않으며, 기대 판정도 그대로 쓴다. 성공 기준 SM1 이 가리키는 "합성 대화 3건"은 이 3건이다. [Q13]

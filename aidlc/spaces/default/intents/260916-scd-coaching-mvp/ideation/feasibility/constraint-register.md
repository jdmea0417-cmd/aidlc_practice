# Constraint Register — SCD 소통 코칭

이 단계에서 확정된 제약을 분류별로 모은다. 각 제약은 출처와 "어겼을 때 무엇이
깨지는가"를 함께 가진다. 출처 태그는 `feasibility-assessment.md` § Sources 와 같다.

상태 표기: **확정** = 사용자가 직접 선택했다 / **파생** = 확정 항목에서 논리적으로
따라 나온다 / **설정값** = 기본값은 있으나 확정하지 않았고 바꿀 수 있다.

TC-16 은 범위 제약 SC-01(클라우드 배포 없음)과 충돌하지 않는다. GitHub Actions 는 애플리케이션을 배포하는 수단이 아니라 병합 전에 검사를 돌리는 수단이며, 서비스가 도는 곳은 여전히 개발자 각자의 로컬 Docker Compose 뿐이다 `[F7]`.

## 4. 규제 제약

**없음 — 사용자 결정에 따른다.**

`[Q5]` 에서 "합성 데이터 전용 테스트이므로 규제 항목은 이번 범위에서 제외한다"가
선택되었다. 이는 규제가 존재하지 않는다는 판정이 **아니라**, 이번 MVP 의 제약으로
기록하지 않겠다는 결정이다. 실사용 데이터로 확장할 때 이 칸은 다시 채워져야 한다
(RAID 로그 A2 참조).

`[intent]` 가 확정한 보호자 열람 권한과 정정·삭제 기능은 **제품 기능**으로 SC-08 에
있으며, 규제 제약이 비어 있다고 해서 줄어들지 않는다.

## 5. 운영 파라미터 (설정값 — 확정하지 않음)

`[Q6]` 에서 "설정값으로만 두고 지금은 확정하지 않는다"가 선택되었다. 기본값은
유지하되 코드에 하드코딩하지 않고 설정으로 노출해야 한다.

| ID | 항목 | 기본값 | 출처 |
|---|---|---|---|
| PM-01 | 녹음 최대 길이 | 5분 | `[spec:01] A-05, [Q6]` |
| PM-02 | Mock 기준 분석 응답 시간 목표 | 3초 이내 | `[spec:01] A-06, [Q6]` |
| PM-03 | "비교 불충분" 기준 | 유효 기회 3회 미만 | `[spec:01] A-07, [Q6]` |
| PM-04 | 원음 보관 기간 | 30일 | `[spec:01] A-08, [Q6]` |

PM-02 는 Mock 기준이며 live 경로에는 적용되지 않는다 `[F2]`. live 응답시간 목표는
제공자가 정해진 뒤에야 세울 수 있다 (RAID 로그 D2).

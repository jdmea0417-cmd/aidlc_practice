## Q1. F01~F07 중 SM1 경로 밖에 있는 F07 을 어떻게 다룹니까?

- C. F07 을 쪼갠다 — 전사 정정(A3)은 Must, 삭제 전파(C5)는 Should

## F1. C5 한 화면 안에 Must 와 Should 가 섞였습니다. 어떻게 나눕니까?

`[spec:03]` C5(자료·공유 설정) 화면은 두 가지를 담고 있습니다.

| C5 의 구성 요소 | 소속 기능 | 이번 답변에서의 등급 |
|---|---|---|
| 보호자·지원자 열람 권한(끄기/요약만/전체) | 보호자 권한 | Q4=A 에 따라 **Must** — "보호자 열람 권한도 실제 계정 위에서 동작한다" |

- B. C5 화면 전체를 Must 로 올린다 — 그러면 F07 의 삭제 전파도 Must 가 되어 Q1 을 B 에서 A 로 바꾸는 셈이다

- D. 권한은 이번에 만들되 화면 없이 계정 데이터와 API 수준까지만 — 설정 화면은 Should
- X. Other (please specify)

[Answer]: C. 보호자 권한을 Should 로 내린다 — Q4 를 A 에서 조정해 권한도 뒤로 미룬다

## F3. F07 이 Must 로 올라오면서 화면 C5 의 어디까지가 Must 가 됩니까?

practices-discovery(2.2)에서 **F07(정정·삭제)이 Should 에서 Must 로 올라갔습니다.**
근거는 합성 대화 S3 의 검증 항목 2(전사 정정 후 재검토 표시)와 4(삭제 시 연결 항목
처리)가 F07 에 걸려 있어, Must 범위만으로는 S3 가 원래 확인하려던 것의 절반을 확인할
수 없다는 것입니다.

F07 의 두 기능이 걸린 화면은 서로 다릅니다.

| F07 의 기능 | 걸린 화면 | 그 화면의 현재 등급 |
|---|---|---|
| 전사 정정 시 재검토 표시 | A3 (전사 확인) | 이미 **Must** — M7 에 포함 |
| 삭제 요청과 연결 항목 전파 | C5 (자료·공유 설정) | **Should** — S3 |

즉 정정 쪽은 이미 Must 인 화면 위에 얹히지만, 삭제 쪽은 Should 인 화면을 열어야
합니다. 앞서 F1 에서 C5 화면 전체를 Should 로 두고 보호자 권한도 함께 뒤로 미루기로
확정했으므로(F1 = C), 그 결정과 F07 승격이 만나는 지점을 정해야 합니다.

C5 화면의 구성 요소는 다음과 같습니다.

| C5 의 구성 요소 | 소속 | F1 = C 에서의 등급 |
|---|---|---|
| 보호자·지원자 열람 권한 전환(NONE/SUMMARY/FULL) | 보호자 권한 | Should |
| 원음 보관 기간 설정, 원음만 삭제 | F07 | Should |
| 기록 삭제 요청과 연결 항목 미리보기 | F07 | Should |
| 서비스 안내 다시 보기 | 공통 | 미분류 |

- A. C5 를 쪼갠다 — 삭제 관련 요소(기록 삭제 요청, 연결 항목 미리보기, 원음만 삭제)만 Must 로 올리고, 보호자 권한 전환과 서비스 안내는 Should 로 남긴다. F1 = C 는 유지된다
- B. C5 화면 전체를 Must 로 올린다 — 삭제와 함께 보호자 권한 전환도 Must 가 되며, 이는 F1 = C 를 뒤집는다
- C. 삭제 기능은 Must 로 만들되 화면 없이 API 수준까지만 — C5 화면 자체는 Should 로 남긴다. S3 의 검증 항목 4 를 화면 없이 확인하게 된다
- D. 정정(A3)만 Must 로 두고 삭제는 Should 로 남긴다 — S3 의 검증 항목 2 만 확인되고 4 는 남는다. 이는 F07 두 기능을 모두 Must 로 올린 결정을 절반으로 되돌린다
- X. Other (please specify)

[Answer]: B. C5 화면 전체를 Must 로 올린다 — 삭제와 함께 보호자 권한 전환도 Must 가 되며, 이는 F1 = C 를 뒤집는다

**변경됨 → F5.** F5 에서 이 답이 무효화하는 확정 항목 8건을 확인한 결과, 사용자가 A(C5 를 쪼갠다)로 바꾸었다. 반영되는 것은 A 다.

현재 순서는 이렇습니다.

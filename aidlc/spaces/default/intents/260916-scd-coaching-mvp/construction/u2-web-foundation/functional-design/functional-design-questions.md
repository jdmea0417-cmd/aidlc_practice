## Q1. 첫 방문 서비스 안내(A1)의 네 항목을 어떤 문구로 씁니까?

요구사항 OQ3 이 이 단계를 담당으로 지정했습니다 — "UI 세부 문구 재작성(A-11) — FR9.2·FR5.2·NFR7
의 실제 문구" `[req]` OQ3. 그중 **FR9.2(첫 방문 서비스 안내)는 U2 의 화면**이므로 여기서 닫습니다
(FR5.2·NFR7 의 리포트 문구는 U5 의 화면이라 U5 의 이 단계가 닫습니다).

지금 정해진 것은 **네 항목이 무엇인지**뿐입니다 — 진단이 아님 / 녹음·데이터 처리 / 이용 한계 /
판정 기준이 공식 척도가 아님 `[req]` FR9.2. 실제 문장은 어디에도 없고, 원본 UI 시안의 문구는
"시안 해상도 한계로 재구성"된 가정(A-11)이라 확정 문구로 쓸 수 없습니다 `[spec:03]` 머리말.

제약: 존댓말·짧은 문장, 금지 표현("사회성 부족", "정상/비정상", "점수", "진단", "치료",
"상대의 진짜 마음", "정답", "실패했어요")은 **허용 문장 목록에 등록된 문장 안에서만** 나타납니다
`[spec:01]` §7, AC1.1.4. 즉 "진단이 아니에요" 처럼 금지 단어를 부정하는 문장은 목록에 등록하고 씁니다.

- A. **제가 네 문장을 초안으로 쓰고, 이 게이트에서 확인받는다** — 위 제약과 기존 문서의 표현을 근거로
  네 문장과 허용 문장 목록을 함께 초안으로 냅니다. 문구가 마음에 안 들면 승인 게이트에서 고칩니다.
  빠르고, 문구가 산출물 안에 남아 코드 생성이 그대로 씁니다
- B. **지금 네 문장을 직접 주신다** — 사용자가 문장을 확정해 주면 그대로 씁니다. 가장 정확하지만
  지금 문장을 만들어야 합니다
- C. **문구를 코드 생성(3.5)으로 넘기고, 이 단계는 "네 항목이 모두 보인다"까지만 적는다** — 설계는
  항목과 배치만 정하고 문장은 구현할 때 씁니다. 지금 멈추지 않지만, OQ3 이 이 단계를 담당으로
  지정했으므로 **배정받은 질문을 다음 단계로 다시 넘기는 것**이 됩니다

## Q2. 동의 여부를 확인하는 `GET /api/v1/me` 가 느리거나 실패하면 앱은 무엇을 보여 줍니까?

동의는 사용자 단위로 **서버에 저장**되고(AC1.1.3), 동의 전에는 다른 화면으로 갈 수 없습니다
(AC1.1.2). 그래서 앱이 뜰 때마다 `GET /api/v1/me` 의 `consentedAt` 을 읽어 어디로 보낼지 정해야
합니다 `[contract]` C1.

정해지지 않은 것은 **그 한 번의 조회가 아직 안 끝났거나 실패했을 때**입니다. AC1.1.1~AC1.1.4 는
동의 전/후만 다루고 이 사이 상태를 다루지 않습니다. NFR9 의 화면 상태 4종은 "비동기 화면"에 걸린
규칙인데, 이건 화면이 아니라 **모든 화면 앞의 관문**이라 그대로 대응되지 않습니다.

- A. **관문 전용 상태 화면을 둔다** — 조회 중에는 전체 화면 로딩, 실패하면 "연결을 확인해 주세요" +
  다시 시도 버튼을 띄우고 **어떤 화면으로도 보내지 않는다**. 동의 전 진입 금지(AC1.1.2)를 확실히
  지키지만, 백엔드가 죽어 있으면 앱이 아무것도 못 합니다
- B. **실패하면 동의 화면으로 보낸다** — 알 수 없으면 "동의 안 함"으로 간주합니다. 안전한 쪽으로
  쏠리지만, 이미 동의한 사용자가 일시적 오류로 안내를 다시 보게 됩니다
- C. **실패하면 마지막으로 확인된 값을 브라우저에 저장해 두고 그것을 쓴다** — 재방문이 부드럽지만,
  동의 여부가 서버 밖에 복제됩니다. AC1.1.3 의 "다른 브라우저로 열어도" 조건과 어긋날 여지가 있습니다

## Q3. 홈(A1)의 "진행 중인 목표 카드"와 "최근 기록 1~2건"을 B1(걷는 뼈대) 시점에 어디까지 만듭니까?

FR9.1 은 홈에 카드 2개 + 진행 중인 목표 카드 + 최근 기록 1~2건 요약을 요구하고, 라우트 `/` 의
소유는 U2 입니다 `[contract]` C17. 그런데 그 두 자리의 **데이터는 다른 단위 소유**입니다 —
진행 중인 목표는 `GET /api/v1/goals`(C5, U6), 최근 기록은 `GET /api/v1/records`(C7, U8).
U6·U8 은 B3·B4 에 있어 B1 보다 뒤입니다 `[bolt]`.

단위 사이 의존은 "계약 합의"로 정해졌으므로(D-92) U2 가 계약만 보고 코드를 쓰는 것은 정해졌습니다.
정해지지 않은 것은 **B1 을 시연할 때 그 두 자리가 어떻게 보이느냐**입니다. B1 의 완료 기준에도
이 두 자리가 없습니다 `[bolt]` B1.

- A. **계약대로 호출하고, 없으면 실패 상태로 보인다** — 두 자리 모두 정식으로 호출합니다. B1 에서는
  경로가 없어 다시 시도 버튼이 보입니다. 나중에 U6·U8 이 들어오면 **U2 를 고치지 않고** 살아납니다.
  대신 뼈대 시연 화면에 오류 자리 두 개가 보입니다
- B. **계약대로 호출하되, 404·501 은 "비어 있음"으로 읽는다** — 아직 없는 경로는 오류가 아니라 빈
  상태로 보입니다. 시연이 깔끔하지만, **진짜 고장과 아직 없음을 화면이 구별하지 못합니다**
- C. **B1 에서는 두 자리를 렌더링하지 않고, U6·U8 이 자기 Bolt 에서 켠다** — 홈은 카드 2개와 하단
  탭만 냅니다. 뼈대가 가장 단순하지만 **AC1.2.1·AC1.2.2 가 B1 에서 통과하지 못하고**, U2 의 화면을
  다른 단위가 나중에 고치게 되어 라우트 소유 규칙(D-101)과 결이 어긋납니다

## Q4. "곧 볼 수 있어요" 공통 안내를 어떤 형태로 만듭니까?

D-73 이 **동작**은 이미 정했습니다 — 화면을 바꾸지 않고, 포커스를 누른 버튼에 두며, 화면 읽기
프로그램에 읽힙니다. 정해지지 않은 것은 **눈에 보이는 형태와 사라지는 방식**입니다. U2 가 이것을
만들고 U6·U7·U8 의 버튼 세 자리(AC6.5.3, AC7.1.4, AC7.3.4)가 그대로 씁니다 `[story]`.

- A. **화면 아래쪽 토스트, 몇 초 뒤 자동으로 사라짐** — 흔한 모양이고 화면을 가리지 않습니다.
  자동으로 사라지므로 **읽는 속도가 느린 사용자가 놓칠 수 있습니다**
- B. **누른 버튼 바로 아래 인라인 안내, 다른 곳을 누를 때까지 남음** — 어떤 버튼에 대한 안내인지
  붙어 있어 분명하고 사라지지 않습니다. 목록 안에서 쓰면 **아래 항목들이 밀립니다**
- C. **작은 대화 상자, 사용자가 닫아야 사라짐** — 가장 확실히 읽히지만 **"화면을 바꾸지 않는다"는
  D-73 의 조건과 가장 멀고**, 닫는 동작이 한 번 더 필요합니다

## Q5. 접근성(NFR2)의 다섯 항목 중 U2 가 구조로 보장하는 것과 각 화면에 맡기는 것을 어떻게 나눕니까?

NFR2 는 다섯 항목을 겁니다 — 접근 가능한 이름, 색만으로 의미 전달 금지, 대비 4.5:1, 터치 영역
44px 이상, 키보드로 SM1 여섯 단계 조작 `[req]` NFR2. U2 는 "접근성 기초(이름표, 포커스 이동, 색
보조 표시)"를 가진다고만 적혀 있고 `[unit]`, **어디까지가 공통이고 어디부터가 각 화면 몫인지**는
정해지지 않았습니다. 화면별 키보드 수용 기준 7개가 기능 단위에 흩어져 있어(AC1.2.4, AC2.1.5,
AC3.2.5, AC4.3.5, AC5.1.6, AC6.2.4, AC8.1.6) 경계를 지금 긋지 않으면 단위마다 달라집니다.

- A. **공통 컴포넌트로 강제한다** — 버튼·입력·카드·탭을 U2 의 공통 컴포넌트로만 만들게 하고, 그
  컴포넌트가 최소 터치 영역·포커스 표시·이름표 필수 속성을 보장합니다. 기능 단위는 그것을 조립만
  합니다. 규칙이 사람의 주의력이 아니라 타입 검사가 되지만, **공통 컴포넌트 목록을 U2 가 지금
  정해야 하고** 나중 화면이 벗어나고 싶을 때 마찰이 생깁니다
- B. **토큰과 지침만 주고 각 화면이 지킨다** — 색·간격·최소 크기를 CSS 토큰으로 주고 규칙은 문서로
  둡니다. 유연하지만 **다섯 항목이 각 단위의 주의력에 남습니다**
- C. **A 에 자동 검사를 더한다** — 공통 컴포넌트에 더해, 대비와 터치 영역을 실제 브라우저에서 재는
  검사(`[browser]` 층)를 U2 가 한 벌 만들어 이후 화면이 같은 검사를 재사용합니다. 가장 확실하지만
  U2 의 범위가 커집니다

reverse-engineering(2.1)은 범위 밖이다. 기존 코드의 모듈 경계가 입력에 없는 것은 결손이 아니라
범위 밖이며, 이 분해는 도메인 설계의 컴포넌트 카탈로그와 스토리만을 근거로 한다.

**이 문서가 정하는 것** — 작업을 나눠 맡는 단위(Unit)와 각 단위가 무엇을 가지고 무엇을 넘기는지.
단위 사이의 인터페이스 모양은 contract-design(2.8), 누가 어느 단위를 언제 만드는지는
delivery-planning(2.9)이 정한다.

**단위는 배포 단위가 아니다** — 배포는 그대로 단일 백엔드(FastAPI) + 프론트엔드(React) +
PostgreSQL 이다 `[practices]`. 단위는 5인이 나눠 맡는 작업 묶음이다. 코드 구조는 도메인 설계의
업무 컴포넌트 6개(`conversation`, `assessment`, `training`, `record`, `account`, `privacy`)와 지원
컴포넌트 2개(WebApp, ProviderAdapters)를 그대로 따르고, 기능 단위는 이 구조를 가로질러 파일을
채운다 `[components]` `[Q1]`.

  지정하지 않은 단위는 Construction 에서 설계 산출물 전체를 받는다 `[Q1]` (D-94).

  는 그 실행 단위 안에 모듈·페이지로 들어가는 단위다.
- **복잡도** — 상대 추정이다(S < M < L < XL). 기준은 만지는 컴포넌트 수, 저장 규칙의 양, 화면 수, E2E
  관여 여부다. 날짜 추정은 2.9 가 한다.

## 단위 정의

### U1 — 백엔드 기반 (`u1-backend-foundation`)

- **kind**: `service` · **배포**: standalone · **복잡도**: L
- **설명**: 모든 백엔드 단위가 기대는 FastAPI 앱 골격과 공통 기반 `[Q2]`.
- **가지는 것**
  - FastAPI 앱 골격과 컴포넌트 6개의 빈 패키지 틀(api / service / repository 세 계층) `[practices]`
  - 설정(pydantic-settings), 분석 모드 판별 — 미설정·모르는 값은 Mock, live 인데 키가 없으면 기동 거부 `[components]`
  - DB 연결, SQLAlchemy 2.0 세션, Alembic 기반
  - 오류 봉투와 request_id, 로그에서 전사 본문 제외
  - ProviderAdapters 의 인터페이스(SttProvider, LlmProvider)와 Mock 구현, 합성 대화 픽스처(S1·S2·S3) `[components]`
  - 시드 고정 사용자(Account, 동의 전 상태)와 동의 저장·조회 API
  - 헬스체크(분석 모드 노출), Docker Compose 한 명령 기동
- **넘기는 것**: 다른 단위가 올라탈 수 있는 실행 가능한 백엔드, Mock 어댑터, 시드·픽스처를 넣는 방법
- **경계**: 기능별 업무 규칙(판정 저장 규칙, 추천, 삭제 전파)은 가지지 않는다. Mock LLM 의 기대 판정
  픽스처 파일 자리는 만들지만 판정 규칙 해석은 U5·U7 이 채운다.
- **구현 메모**: 팀 관행의 걷는 뼈대(업로드 → 전사 → DB → Mock → 화면)는 U1·U2 위에서 U3 가 관통한다
  `[practices]` `[stories]`. 기반을 먼저 닫아야 다른 단위가 시작할 수 있다 `[Q5]`.

### U2 — 화면 기반 (`u2-web-foundation`)

- **kind**: `ui` · **배포**: standalone · **복잡도**: M
- **설명**: 모든 화면 단위가 기대는 React 앱 틀과 공통 컴포넌트 `[Q2]`.
- **가지는 것**
  - 앱 틀, 하단 탭, 라우팅(화면 ID + 영어 역할 이름) `[components]`
  - 얇은 API 클라이언트(오류 봉투 → 타입 있는 오류)
  - 화면 상태 4종(로딩/성공/실패·다시 시도/비어 있음) 공통 컴포넌트
  - 아직 없는 Should 화면용 "곧 볼 수 있어요" 안내(D-73)
  - 첫 방문 동의 화면과 동의 전 이동 막기, 홈(US1)
  - 접근성 기초(이름표, 포커스 이동, 색 보조 표시), 반응형 모바일 기준 레이아웃
- **넘기는 것**: 기능 단위가 페이지만 끼워 넣으면 되는 앱 틀
- **경계**: 기능 화면(A2~A5, B1~B5, C1, C5)은 각 기능 단위가 만든다. 노트북 레이아웃은 U13.

### U3 — F01 녹음·전사 (`u3-f01-capture`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: L
- **설명**: 실제 대화를 파일 업로드와 브라우저 직접 녹음 두 경로로 가져오고, 전사를 확인·정정한다.
- **가지는 것**
  - Conversation 컴포넌트: 대화 생성·처리 상태, 음성 파일 검증·저장(DB 행 대기 → 파일 → DB 행 완료), 발화, 정정 이력, 전사 버전
  - 정정 시 "발화 정정됨" 사건을 알리는 쪽 `[decisions]` ADR-009
  - 화면: 업로드(A2), 직접 녹음(A2-R), 전사 확인·발화 고치기(A3)
- **넘기는 것**: 전사가 끝난 대화와 발화 — U5 의 분석 입력
- **경계**: 맥락 입력은 U4, 재검토 안내와 재분석은 U9, 삭제는 U9.

### U4 — F02 맥락 구조화 (`u4-f02-context`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: S
- **설명**: 대화의 맥락 네 항목(관계·장소·목적·사용자 목표)을 값과 상태로 저장한다.
- **가지는 것**: Conversation 컴포넌트의 ContextInfo 저장·조회, "잘 모르겠어요" → 미상, 맥락 입력 화면(A2 흐름 안)
- **넘기는 것**: 분석 전제로 쓰일 맥락 — U5 가 읽는다
- **경계**: 리포트에서 맥락 수정으로 가는 버튼(US4.3)은 U5 가 만들고 이 단위의 화면으로 이동시킨다.

### U5 — F03 수행 평가 (`u5-f03-assessment`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: XL
- **설명**: 실제 대화 분석과 판정 저장, 리포트. 판정 저장의 유일한 입구 `[components]`.
- **가지는 것**
  - Assessment 컴포넌트: 사회적 사건, 행동 판정, 근거, 버전 값 객체(ADR-003), 근거 규칙(ADR-008), 판정 대체 연결 필드(ADR-007)
  - 판정 저장 규칙 전부 — 연습 시도 판정도 이 규칙을 거친다(ADR-004)
  - Mock LLM 기대 판정 픽스처 해석
  - 리포트(A4): 잘한 장면·어려움 장면(PARTIAL 두 곳 배치), 보류 이유, 근거 보기, 맥락 수정·목표 연습으로 이동, "분석이 이상해요"
- **넘기는 것**: 저장된 판정 — U6(목표 추천), U7(시도 판정 저장), U8(추이), U9(재검토·재분석)
- **경계**: 재검토 필요 표시와 재분석 흐름은 U9 가 이 컴포넌트에 더한다.
- **구현 메모**: 핵심 경로의 분석 파이프라인(AC4.1.2~AC4.1.4)이 여기 있다 `[stories]`. 가장 큰 단위라 2.9 에서
  갈래 배정 시 우선 고려 대상이다.

### U6 — F04 목표·추천 (`u6-f04-goal`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: M
- **설명**: 리포트 판정에서 목표 1~3개를 추천하고, 고른 목표를 연습으로 잇는다.
- **가지는 것**: Training 컴포넌트의 TrainingGoal, 목표 추천(Recommendation, 목표 추천 종류), 충분성 부족 시 일반 연습 안내, 선택 결과 저장, 목표 선택 화면(A5)
- **넘기는 것**: 선택된 목표 ID — U7 의 연습 시작 입력
- **경계**: 다음 코칭 추천(C1)은 U8, 반복 어려움·선택 이력 반영은 U14 `[decisions]` ADR-002.

### U7 — F05 모의 대화 (`u7-f05-practice`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: L
- **설명**: 연습 목록에서 상황을 골라 도움 없이 첫 시도, 단계별 힌트, 다시 시도, 비교까지.
- **가지는 것**: Training 컴포넌트의 시나리오 원형·변형, 연습 세션, 시도(수정 불가, 순번), 힌트, 일시정지·힌트 제안 입력 규칙, 시도 판정 후보 요청과 Assessment 로 저장 요청, 화면 B1~B5
- **넘기는 것**: 연습 기록과 시도 판정 — U8 이 읽는다
- **경계**: 판정 저장 규칙 자체는 U5.

### U8 — F06 기록·다음 추천 (`u8-f06-record`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: M
- **설명**: 기록 목록, 목표별 추이(독립·도움 후 분리), 다음 코칭 추천, SM1 종단 리허설.
- **가지는 것**
  - Record 컴포넌트(자기 엔티티 없음, ADR-010): 기록 목록 필터, 추이 집계와 비교 불충분 판정
  - Training 의 다음 코칭 추천 — Must 규칙(가장 최근 어려움 장면 하나)
  - 기록 화면(C1), 실제 대화 목록 탭
  - SM1 종단 리허설 E2E(US9.3)
- **넘기는 것**: 성공 기준 SM1 의 판정 자료
- **경계**: 상세 조회는 U10, 보호자 열람 데이터는 U12, 추천 고도화는 U14.
- **구현 메모**: US9.3 을 여정의 마지막 단계인 이 단위에 두었다 `[stories]` (D-94). 이 스토리의 수용 기준
  (AC9.3.1)은 동의 → 업로드 → 전사 확인 → 리포트 → 목표 선택 → 모의 대화 → 기록 흐름이 통합되어야 통과한다 —
  아래 열린 질문 OQ-U3 참고.

### U9 — F07 정정·삭제 (`u9-f07-correction-deletion`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: L
- **설명**: 정정 뒤 재검토 안내와 재분석, 대화 삭제와 원음만 삭제.
- **가지는 것**
  - 재검토 흐름: "발화 정정됨" 구독 → 재검토 필요 표시 → "판정 재검토 필요" → 추천 재계산 대기(ADR-009), 재분석과 판정 대체 연결(ADR-007)
  - Privacy 컴포넌트: 삭제 요청·미리보기·영향 항목·목표 삭제/유지, 한 트랜잭션 DB 삭제 → 커밋 → 파일 삭제, 남은 파일 추적(ADR-006)
  - Conversation·Assessment·Training 의 데이터 정리 인터페이스
  - 원음만 삭제, 삭제 화면(C5 의 Must 부분), A3 상단 재검토 안내
- **경계**: 보호자 열람 권한·원음 보관 기간 설정은 U12.

### U10 — 상세 조회 (`u10-s-detail-views`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: M
- **설명**: 목표 상세와 시도 이력, 연습 기록 상세, 실제 대화 상세와 정정 이력 (Should).
- **가지는 것**: Record 컴포넌트의 상세 조회 응답과 상세 화면 셋. U2 의 "곧 볼 수 있어요" 안내 자리를 실제 화면으로 바꾼다.
- **넘기는 것**: 목표·연습·실제 대화의 상세 조회 응답 — 보호자 열람(U12)이 FULL 권한에서 같은 모양을 재사용할 수 있다
- **경계**: 기록 목록과 추이 집계는 U8, 정정 이력을 만드는 쪽은 U3·U9 다. 이 단위는 읽기만 한다(ADR-010).

### U11 — 계정·로그인 (`u11-s-account-auth`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: M
- **설명**: 사용자가 자기 계정을 만들고 로그인한다 (Should).
- **가지는 것**: Account 컴포넌트의 회원가입·로그인·세션, 인증 확인 경로, 로그인 화면
- **경계**: Must 경로의 시드 고정 사용자(U1)를 없애지 않는다 — 시연은 로그인 없이 계속 돈다(US9.2).

### U12 — 보호자·공유 (`u12-s-guardian-sharing`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: L
- **설명**: 보호자 초대와 열람 권한, 보호자 열람 화면, 원음 보관 기간 설정 (Should).
- **가지는 것**: GuardianInvitation, SharingSetting(NONE/SUMMARY/FULL), Privacy 의 권한 판정, Record 의 보호자 열람 데이터, 원음 보관 기간 설정과 서비스 안내 다시 보기(C5 의 Should 부분)
- **의존 메모**: 이 단위만 다른 기능 단위(U11)의 구현 완료에 의존한다. 보호자가 로그인해야 열람이 성립하므로
  계약만으로 대신할 수 없다 `[Q6]` (D-92).

### U13 — 노트북 레이아웃 (`u13-s-laptop-layout`)

- **kind**: `ui` · **배포**: embedded · **복잡도**: S
- **설명**: 노트북 브라우저 너비에서 화면이 제대로 보이게 한다 (Should).
- **가지는 것**: 넓은 화면 레이아웃 규칙과 기존 화면 점검. 백엔드 변경 없음.
- **넘기는 것**: 노트북 너비에서 점검을 마친 화면 목록
- **경계**: 모바일 기준 레이아웃과 공통 틀은 U2 가 가진다. 이 단위는 화면의 기능이나 문구를 바꾸지 않는다.

### U14 — 추천 고도화 (`u14-s-recommendation-plus`)

- **kind**: 지정 안 함 · **배포**: embedded · **복잡도**: M
- **설명**: 쌓인 기록(반복 어려움, 도움 후 성공, 선택 이력)을 반영한 다음 코칭 추천 (Should).
- **가지는 것**: Training 의 다음 코칭 추천 규칙 확장. U8 의 Must 규칙을 대체하지 않고 넓힌다(D-78, D-80).
- **넘기는 것**: 기록(C1)에 싣는 다음 코칭 추천 — 응답 모양은 U8 의 것을 그대로 쓴다
- **경계**: 목표 추천(A5)은 U6, 추천 재계산 대기 표시는 U9 가 가진다.

## 같은 코드를 여러 단위가 만지는 자리

기능 단위가 컴포넌트를 가로지르므로 한 컴포넌트·한 화면에 여러 단위가 파일을 쓴다 `[Q1]`.
충돌을 줄이려면 contract-design(2.8)에서 아래 경계를 먼저 고정해야 한다.

| 자리 | 만지는 단위 | 나누는 방법 |
|---|---|---|
| 화면 A2 (업로드·맥락 입력) | U3, U4 | 업로드 흐름 안에서 맥락 입력 구간을 U4 컴포넌트로 끼운다 |
| 화면 A3 (전사 확인) | U3, U9 | 상단 재검토 안내 영역을 U9 가 채운다 |
| 화면 A4 (리포트) | U5, U9 | 재분석 뒤 대체된 판정 대신 새 판정을 고르는 조회 조건(ADR-007)은 U9 가 더한다 |
| Conversation 컴포넌트 | U3, U4, U9 | 엔티티별 — 발화·정정(U3), 맥락(U4), 정리 인터페이스(U9) |
| Assessment 컴포넌트 | U5, U7, U9 | 저장 규칙은 U5 단독, U7 은 저장을 호출만, U9 는 재검토·대체 연결 |
| Training 컴포넌트 | U6, U7, U8, U9, U14 | 엔티티별 — 목표·목표 추천(U6), 시나리오·세션·시도(U7), 다음 코칭 추천(U8·U14), 정리 인터페이스와 "판정 재검토 필요" 구독 → 추천의 재계산 대기 표시(U9, ADR-009) |
| Record 컴포넌트 | U8, U10, U12 | 목록·추이(U8), 상세(U10), 보호자 열람(U12) |

## Q1. 작업 단위를 무엇을 기준으로 자릅니까?

5인이 동시에 맡을 수 있게 컴포넌트를 작업 단위로 묶어야 합니다. 팀 관행은 같은 화면을 만지는
스토리는 한 사람이 순서대로, 기능 이름(conversation 등)이 백엔드 세 계층과 맞물리게 나누기로
했습니다 `[practices]`. 업무 컴포넌트는 6개, 화면 코드(WebApp)는 하나의 지원 컴포넌트입니다
`[components]`.

- A. **컴포넌트별 세로 단위** — 업무 컴포넌트 하나와 그 화면을 한 단위로 묶는다(예: 대화 단위 = Conversation 백엔드 + A2·A2-R·A3 화면). 한 사람이 백엔드부터 화면까지 끝낸다
- B. **백엔드와 화면을 따로** — 업무 컴포넌트마다 백엔드 단위를 두고, 화면은 별도 화면 단위(하나 또는 흐름별)로 둔다
- C. **기능(F01~F07) 단위** — 컴포넌트를 가로질러 기능 하나씩 단위로 삼는다(예: F03 수행 평가 = Assessment + ProviderAdapters 판정 + A4)
- D. **큰 단위 3개** — 실제 대화(Conversation+Assessment), 연습(Training), 기록·자료(Record+Privacy+Account)

## Q4. 5인이 동시에 붙을 병렬 갈래는 몇 개로 잡습니까?

Scope Definition 에서 "작업 단위 분해 단계에서 정한다"로 미룬 결정입니다(D-47) `[log]`. 갈래 수는
의존 관계가 없어 동시에 진행할 수 있는 단위 묶음의 최대 개수를 뜻합니다. 인원은 5인 전원
풀스택이고, 리뷰는 만들지 않은 사람 1인이 합니다 `[practices]`. 누가 어느 갈래를 맡는지는 이 단계가
아니라 delivery-planning(2.9)이 정합니다.

- A. 3갈래 — 한 갈래에 1~2명, 남는 사람이 리뷰·통합·E2E 를 맡을 여유가 있다
- B. 4갈래 — 한 갈래에 1명 이상, 1명이 기반·통합을 맡는다
- C. 5갈래 — 한 사람에 한 갈래, 병렬도가 가장 높지만 리뷰가 서로 교차해야 한다
- D. 갈래 수를 고정하지 않는다 — 의존 관계가 허락하는 만큼 병렬로 두고, 인원 배분은 2.9 가 정한다
- X. Other (please specify)

[Answer]: B. 4갈래 — 한 갈래에 1명 이상, 1명이 기반·통합을 맡는다

## Q5. 기능 단위의 의존을 "구현 완료"로 봅니까, "계약 합의"로 봅니까?

Q1 에서 기능(F01~F07) 단위, Q4 에서 4갈래를 정하셨습니다. 그런데 기능끼리의 의존을 **구현이 끝나야
다음을 시작**으로 보면 흐름이 거의 한 줄입니다 — 가져오기(F01) → 맥락(F02) → 평가(F03) → 목표(F04)
→ 모의 대화(F05) → 기록(F06), 정정·삭제(F07)는 F01·F03·F05·F06 뒤 `[components][stories]`. 이렇게 두면
기반 단위가 끝난 직후에는 동시에 시작할 수 있는 기능 단위가 F01 하나뿐이라, 초반에는 4갈래를 채울 수
없습니다. 다음 단계인 계약 설계(2.8)가 단위 사이의 인터페이스를 먼저 정하므로, 계약과 시드 데이터로
앞 단위를 대신하면 병렬로 시작할 수 있습니다(개발자 검토가 "S1 분석 완료 + 목표 선택됨" 시드를 제안했었다
`[stories]`).

- A. **계약 기준** — 기능 단위는 기반 단위 둘에만 "구현 완료" 의존을 두고, 다른 기능 단위와는 계약(2.8)과 시드·픽스처로 연결한다. 기반이 끝나면 여러 기능 단위가 함께 시작할 수 있다
- B. **구현 완료 기준** — 흐름 순서대로 의존을 둔다. 4갈래는 "최대" 병렬 수이고 초반에는 갈래가 비는 것을 받아들인다
- C. **섞어서** — 판정 결과를 직접 읽어야 하는 곳(F03 → F04, F03·F05 → F06)만 구현 완료 의존을 두고, 나머지는 계약 기준으로 둔다
- D. 계약 기준으로 두되, 정정·삭제(F07)만은 다른 기능이 모두 끝난 뒤 시작한다(구현 완료 의존)
- X. Other (please specify)

[Answer]: A. **계약 기준** — 기능 단위는 기반 단위 둘에만 "구현 완료" 의존을 두고, 다른 기능 단위와는 계약(2.8)과 시드·픽스처로 연결한다. 기반이 끝나면 여러 기능 단위가 함께 시작할 수 있다

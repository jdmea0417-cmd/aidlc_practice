## P1. 주 사용자 — "지민" (13–18세, 중·고등학생)

| 항목 | 내용 | 출처 |
|---|---|---|
| 역할 | 실제 대화를 올리고, 리포트를 읽고, 목표를 골라 모의 대화로 연습한다 | `[intent]` |
| 목표 | 어느 말에서 대화가 어긋났는지 이해할 수 있는 말로 돌아본다 / 고른 목표를 바로 연습해 본다 / 나아지는지 확인한다 | `[intent]` Target Customer |
| 불편 | 대화가 끝나면 "잘 안 됐다"는 인상만 남는다 / 무엇을 연습할지 이어지지 않는다 / 실패로 규정당하는 것이 싫다 | `[intent]` Problem Statement |
| 맥락 | 조별 과제, 동아리, 급식실·쉬는 시간, 교사와의 대화, 진로 상담 같은 학교 생활 | `[intent]` (D-17) |
| 기기 | 휴대폰 브라우저(모바일 폭). 노트북 폭은 나중에 지원 | `[req]` NFR1, FR15 |
| 기술 친숙도 | 중간 — 채팅과 녹음 앱에 익숙하다 | 작업 가정 |
| 이용 빈도 | 대화가 기억에 남을 때 수시로 | 작업 가정 |
| 주의할 점 | 의사소통에 어려움이 있으므로 문구는 짧은 존댓말, 판단보다 관찰로 말한다. 금지 표현을 쓰지 않는다 | `[req]` NFR7, `[spec:01]` §7 |
| 설계 전제 (작업 가정) | 명시되지 않은 뜻을 추론하거나 비유·중의적 표현을 이해하는 데 어려움이 있을 수 있다. 문구는 글자 그대로 읽혀도 뜻이 같아야 하고, 화면은 사용자의 동작 없이 바뀌지 않는다(녹음 5분 도달 시 자동 업로드하지 않음, 반응 없는 버튼 대신 안내). SCD 의 일반적 특성에서 온 전제이며 실제 사용자 조사로 확인한 것이 아니다 | `[contrib:design]` |
| 기기 입력 | 휴대폰 한글 키보드. 한글 조합 중 Enter 가 두 번 전송되지 않아야 한다 | `[contrib:design]` |

## P2. 보호자·의사소통 지원자 — "보호자" (Should 기능)

| 항목 | 내용 | 출처 |
|---|---|---|
| 역할 | 사용자가 허용한 범위에서 결과를 **열람만** 한다 | `[intent]` (D-25) |
| 목표 | 아이가 무엇을 연습하고 있는지, 추이가 어떤지 본다 / 허용된 경우 리포트까지 본다 | `[req]` FR14.4 |
| 불편 | 허락 없이 보는 것은 원하지 않는다 / 데이터 보관과 삭제가 통제되는지 알고 싶다 | `[intent]` Target Customer |
| 접근 | 자기 계정으로 로그인하고 사용자의 초대로 연결된다. 보호자 전용 읽기 화면에서 본다 | `[req]` FR14.2·FR14.3 (D-69) |
| 볼 수 있는 것 | SUMMARY = 목표와 목표별 추이 / FULL = 거기에 리포트. 전사 원문과 원음은 보지 않는다 | `[req]` FR14.4 |
| 등급 | 이 페르소나의 스토리는 모두 Should 다 — 취소가 아니라 만드는 시점만 뒤로 갔다 | `[scope]` (D-44) |

## P3. 시연 운영자 — "시연 운영자" (스토리 작성용)

| 항목 | 내용 | 출처 |
|---|---|---|
| 역할 | 2026-11-05 시연과 리허설에서 로컬 환경을 띄우고 합성 대화로 종단 흐름을 돌린다 | `[Q1][FU1]` (D-71), `[practices]` Deployment |
| 목표 | 한 명령으로 띄우고 분석 모드가 Mock 인지 확인한다 / 합성 대화 3건을 골라 흐름을 시작한다 | `[req]` NFR5, NFR10, FR1.5, FR11.1 |
| 불편 | 설정이 어긋나 live 로 흐르거나 첫 요청에서 터지는 일 / 로그인 같은 준비 절차 | `[req]` NFR5 |
| 맡는 요구사항 | FR1.5, FR11.1, NFR5, NFR10 **네 항목만** | `[FU1]` (D-71) |
| 성격 | **이해관계자가 아니다.** 이해관계자는 제품을 쓰는 사람(P1, P2)뿐이라는 결정(D-23)은 그대로이며, 이 페르소나는 화면이 없는 요구사항을 스토리 형식으로 쓰기 위해서만 둔다 | `[log]` D-23, D-71 |

## 페르소나 관계와 우선순위

| 순위 | 페르소나 | 이유 |
|---|---|---|
| 1 | P1 주 사용자 | 성공 기준 SM1 의 여섯 단계가 전부 이 사람의 흐름이다 |
| 2 | P3 시연 운영자 | SM1 을 실제로 실행하는 사람. Must 경로를 여는 준비 절차를 맡는다 |
| 3 | P2 보호자 | P1 의 허락으로만 연결되며 기능은 Should 다 |

```
P1 주 사용자 ──(초대·권한 NONE/SUMMARY/FULL, Should)──> P2 보호자
      ^
      |
P3 시연 운영자 (환경 기동·합성 대화 파일 준비 — P1 의 흐름을 시작시킴)
```
